# Android resources (staged)

Socia-branded Android resources committed to the repo **before** the full
Gradle/Android Studio project exists. They are generated by
`scripts/generate-android-icons.mjs` from the master logo at
`resources/icon-source.png` and installed into the live Android project by
`scripts/install-android-icons.mjs`.

## Why staged here (not directly in `android/`)

The Replit container doesn't ship the Android SDK, so `npx cap add android`
(which creates `build.gradle`, Java sources, `AndroidManifest.xml`, etc.)
must be run on a developer machine. Capacitor refuses to run `cap add
android` when an `android/` folder already exists — so pre-creating the
launcher PNGs under `android/app/src/main/res/` would permanently block the
platform from being added. Instead we keep them in this staging tree and
copy them in after `cap add android` succeeds.

## Workflow on a developer machine

(Requires Android SDK + JDK 17.)

```bash
# 1. Regenerate if the source logo changed
pnpm --filter @workspace/socia icons:generate

# 2. One-time: add the native Android platform
pnpm --filter @workspace/socia cap:add:android

# 3. Overlay the Socia-branded resources on top of Capacitor's defaults
pnpm --filter @workspace/socia icons:install

# 4. Apply the AndroidManifest.xml edits below (one-time)

# 5. Build / open in Android Studio
pnpm --filter @workspace/socia cap:sync
pnpm --filter @workspace/socia cap:open:android
```

`icons:install` is non-destructive: it copies file-by-file and only
touches paths the generator owns. Re-run it any time you change the logo
or re-run `cap sync`.

## What's generated

```
resources/android-res/
├── drawable/
│   ├── ic_stat_notify.png         (monochrome 24dp notification icon)
│   └── splash.png                 (1080×1920 branded splash, centered logo)
├── mipmap-mdpi/ … mipmap-xxxhdpi/
│   ├── ic_launcher.png            (legacy square launcher,  48 → 192 px)
│   ├── ic_launcher_round.png      (legacy round launcher,  48 → 192 px)
│   └── ic_launcher_foreground.png (adaptive FG, 108 → 432 px, 66% safe)
├── mipmap-anydpi-v26/
│   ├── ic_launcher.xml            (adaptive icon: foreground + background)
│   └── ic_launcher_round.xml      (same, used by round-shape launchers)
└── values/
    ├── colors.xml                 (brand colors + splashBackground #05060B)
    ├── ic_launcher_background.xml (adaptive BG color)
    └── styles.xml                 (AppTheme + SplashTheme for Android 12+)
```

## AndroidManifest.xml edits (one-time, after `cap add android`)

Open `android/app/src/main/AndroidManifest.xml` and apply:

```xml
<application
    android:icon="@mipmap/ic_launcher"
    android:roundIcon="@mipmap/ic_launcher_round"
    android:label="@string/app_name"
    android:theme="@style/AppTheme">

    <!-- Launcher activity uses SplashTheme so the very first frame is
         the branded dark splash, not a white system flash. -->
    <activity
        android:name=".MainActivity"
        android:theme="@style/SplashTheme"
        android:exported="true">
      <intent-filter>
        <action android:name="android.intent.action.MAIN"/>
        <category android:name="android.intent.category.LAUNCHER"/>
      </intent-filter>
    </activity>

    <!-- Fallback notification icon (FCM / @capacitor/local-notifications). -->
    <meta-data
        android:name="com.google.firebase.messaging.default_notification_icon"
        android:resource="@drawable/ic_stat_notify"/>
    <meta-data
        android:name="com.google.firebase.messaging.default_notification_color"
        android:resource="@color/colorAccent"/>
</application>
```

Capacitor's scaffold sets `android:theme="@style/AppTheme.NoActionBarLaunch"`
on the launcher activity — replace it with `@style/SplashTheme` so the
Android 12+ themed splash kicks in.

## Updating the logo

Drop a new high-res square PNG (≥1024×1024 recommended) at
`resources/icon-source.png`, then re-run:

```bash
pnpm --filter @workspace/socia icons:generate
pnpm --filter @workspace/socia icons:install   # only on a machine with android/ already added
```
